# PostgreSQL 备份与灾难恢复手册

> 当前能力边界：`GET /v1/admin/backup/manifest` 只返回 schema 和迁移清单，不会执行备份或恢复。
> 在项目补齐自动化前，以下是部署者必须执行的 Manual-First 合同。

## 1. 必须成套保管的资产

1. PostgreSQL 自定义格式备份。
2. `HUAKAI_CREDENTIAL_KEY_B64` 及其版本信息。
3. 会话签名密钥。
4. 日志账本 Ed25519 私钥和公钥。
5. Hermes JWT 密钥和内部令牌，若已启用。
6. Caddy 证书卷可重新签发，但生产切换前应确认 ACME 账户和限流风险。
7. 当前 Git commit、镜像摘要和数据库迁移版本。

只恢复数据库而没有原凭据加密密钥，会得到无法解密的账号库；只恢复密钥而没有数据库也无法恢复业务。

## 2. 备份

以下示例从 PostgreSQL 容器输出到宿主持久目录，文件名应包含 UTC 时间和 commit：

```bash
mkdir -p /srv/huakai-backups
chmod 700 /srv/huakai-backups
cd backend
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_dump -U huakai -d huakai -Fc \
  > /srv/huakai-backups/huakai-YYYYMMDDTHHMMSSZ-COMMIT.dump
chmod 600 /srv/huakai-backups/huakai-*.dump
```

校验备份结构：

```bash
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_restore --list \
  < /srv/huakai-backups/huakai-YYYYMMDDTHHMMSSZ-COMMIT.dump \
  > /srv/huakai-backups/huakai-YYYYMMDDTHHMMSSZ-COMMIT.list
test -s /srv/huakai-backups/huakai-YYYYMMDDTHHMMSSZ-COMMIT.list
```

数据库备份与密钥包应分别加密并保存在至少两个故障域；不能只留在同一台服务器的数据盘。

## 3. 隔离恢复演练

恢复演练不得覆盖生产库：

1. 创建与生产隔离的 PostgreSQL 16 实例。
2. 创建空数据库。
3. 使用 `pg_restore --clean --if-exists --no-owner` 恢复。
4. 只在隔离环境加载对应密钥。
5. 运行迁移版本查询、关键表计数、凭据解密自检和只读健康检查。
6. 启动不暴露公网的 Gateway，验证 `/readyz`。
7. 记录备份时间、恢复开始/完成时间、数据校验、RPO 和实际 RTO。
8. 销毁隔离环境中的明文秘密和恢复库。

没有成功的隔离恢复演练，不能把“生成了 dump”写成备份闭环。

## 4. 生产恢复

1. 摘除所有公网流量，停止 Gateway、worker 和 Hermes。
2. 保存当前故障库和日志证据，不在原数据卷上反复尝试破坏性命令。
3. 新建干净 PostgreSQL 实例或数据卷。
4. 恢复与 dump 同批的密钥和版本信息。
5. 执行 `pg_restore`。
6. 如果应用版本高于备份 schema，只允许执行已验证的前向迁移。
7. 启动 Gateway，检查凭据自检、`/readyz`、日志健康、DLQ、待对账 usage 和媒体孤儿。
8. 用脱敏测试租户和测试 Key 验证身份、路由、账号、结算和退款查询。
9. 小流量恢复，观察后再全量。

## 5. 失败判据

- dump 为空、`pg_restore --list` 失败或校验和不匹配。
- 恢复后迁移版本异常或数据库 dirty。
- 凭据密钥自检失败。
- 日志签名密钥与账本不匹配。
- `/readyz` 非 200。
- 余额、账本、claim、退款或恢复队列出现不一致。

出现任一项都不得接生产流量。
