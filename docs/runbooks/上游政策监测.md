# 上游政策监测手册

> 工具：`tools/upstream-policy-monitor`
> 能力边界：只读取公开官方页面、状态 JSON 和 GitHub API 元数据；输出是变化线索，不是源码能力证据。

## 1. 本地验证

```bash
python3 -m py_compile tools/upstream-policy-monitor/run.py
bash -n tools/upstream-policy-monitor/run.sh
python3 -m unittest tools/upstream-policy-monitor/test_run.py
```

## 2. 不写文件的检查

```bash
tools/upstream-policy-monitor/run.sh --no-write
```

只有命令退出成功且输出中没有抓取失败，才算本轮扫描有效。网络失败不能被解释成“没有变化”。

## 3. 生产定时运行

产物写到仓库外的持久运维目录：

```bash
install -d -m 700 /var/lib/huakai/upstream-policy-monitor
tools/upstream-policy-monitor/run.sh \
  --live \
  --output-dir /var/lib/huakai/upstream-policy-monitor
```

不要把周期产物写入 `docs/alerts`，也不要提交 Git。cron 或 systemd 只在部署主机配置，不由仓库
自动安装。

## 4. 告警处理

1. 确认变化来自官方来源，而不是页面抓取失败或模板变化。
2. 找到受影响的厂商、账号模式、协议、模型或政策关键词。
3. 检查近期 Release、Changelog、公开 Issue 和生产源码。
4. 在 HUAKAI 当前主线沿账号导入、凭据刷新、模型发现、出站、错误分类、计费和恢复核实影响。
5. 只有完成源码或真实复现后，才创建缺陷或升级 Issue。

监测器不能证明：

- 某厂商已经封禁或允许某种用法。
- 借鉴项目已经实现或缺少某能力。
- HUAKAI 当前一定受影响。

这些结论仍需官方规范、生产源码或真实复现。
