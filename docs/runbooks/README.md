# HUAKAI 运维手册索引

> 事实基线：`origin/main@71abcf8e`
> 原则：Runbook 只保留当前可执行步骤；历史故障、旧迁移和一次性测试由 Git、Issue、PR、CI 记录。

## 使用顺序

1. 先看 [《生产部署与升级手册》](../deploy/生产部署与升级.md) 确认拓扑、迁移和 readiness。
2. 根据故障对象选择一个专题手册。
3. 先查询状态和影响范围，再执行恢复动作。
4. 钱、权限、凭据和不确定上游副作用禁止直接改表。
5. 处理后验证最终状态、日志和告警已经收敛。

## 统一严重度

| 级别 | 现场含义 | 首要动作 |
| --- | --- | --- |
| S0 | 秘密泄漏、跨租户、错误资金效果、不可逆数据损坏 | 立即摘流、阻止继续副作用、保护证据、通知 Owner |
| S1 | 核心链路不可用、结算或权限状态不收敛、广泛错误 | 限制影响面，按专题恢复，修复前不恢复全流量 |
| S2 | 局部功能退化、有明确替代路径 | 记录 Issue，按业务优先级修复 |
| S3 | 展示、措辞或低风险维护问题 | 正常排期 |

## 统一禁止项

- 不把真实 token、Cookie、Key、私钥、数据库密码或用户原始正文贴进 Issue、PR 和日志。
- 不绕过 Caddy 暴露 Gateway 的 8080。
- 不用 SQL 直接补余额、退款、claim、账本、幂等效果或 DLQ 状态。
- 不在未确认上游是否成功时直接重放图片、视频、支付或其他不可逆请求。
- 不用 `migrate down 1` 猜测回滚。
- 不把普通日志 30 天清理扩大到资金和幂等业务事实。
