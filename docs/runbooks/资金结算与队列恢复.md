# 资金结算、DLQ 与人工恢复手册

## 1. 先区分恢复对象

| 对象 | 含义 | 主要入口 |
| --- | --- | --- |
| 业务 DLQ | 可幂等重放的业务副作用 | `/admin/v1/dlq/{handler}` |
| 通知/观测 DLQ | 邮件、通知或观测交付失败 | `/admin/v1/obs-dlq` |
| Settlement Intent | 已交付响应后的结算状态不确定 | usage 待对账与结算恢复 worker |
| 强配额恢复 | reservation 终结失败或孤儿预留 | quota reconciliation worker |
| 媒体孤儿 | 上游任务可能已提交、本地状态不确定 | `/admin/v1/media-task-orphans` |
| 退款/争议 | 已有费用需要部分或累计补偿 | 退款、争议和余额账本入口 |

不同队列不能相互替代。重放前先确认副作用是否已经发生。

## 2. 业务 DLQ

```text
GET  /admin/v1/dlq/{handler}
POST /admin/v1/dlq/{id}/replay
```

处理步骤：

1. 查看 handler、状态、幂等键、最后错误、重试次数和影响对象。
2. 修复数据库、上游、密钥或配置根因。
3. 确认该任务可安全重放。
4. 执行 replay。
5. 验证状态变为 delivered 或目标业务事实已完成。

409 表示状态冲突，不能并发重复重放；503 表示本次重放仍失败。

## 3. 待结算用量与强配额

查询待对账 usage：

```text
GET /admin/v1/usage?pending_reconciliation_only=true
```

正常目标是待对账逐步收敛到 0。已交付响应后的结算任务不能因普通重试上限被静默丢弃。
强配额 reservation 终结失败由持久任务和孤儿扫描收敛；不要直接释放数据库行来“解冻”。

## 4. 媒体孤儿

上游视频或媒体创建可能已经成功，本地超时不等于上游失败。处理时：

```text
GET  /admin/v1/media-task-orphans
POST /admin/v1/media-task-orphans/{id}/reconcile
```

列表默认返回 100 条、最多 1000 条当前 `pending` 记录。当前代码中，`platform_admin` 默认可以
查看全部租户并用 `tenant_id` 收窄，`tenant_operator` 被强制限制到自身租户；这是尚未完全收紧的
三身份旧权限，不能把它误写成最终产品边界。

处理步骤：

1. 使用保存的上游任务身份查询真实状态。
2. 能证明任务成功时提交 `{"status":"reconciled"}`，默认只标记，不扣钱。
3. 只有明确需要追扣且原 hold 仍可结算时，才提交
   `{"status":"reconciled","back_charge":true,"reason":"..."}`。
4. 能证明未提交时使用 `cancelled`；决定保留线索但不再处理时使用 `ignored`。
5. 无法证明时保持 `pending`，不要为了清空列表强行对账。
6. 追扣没有真正发生时接口返回 409、孤儿继续保持 `pending`；根据
   `back_charge_outcome` 调查，不自动制造新扣款。

最终状态使用 `reconciled`、`cancelled` 或 `ignored` 等明确结果，不删除线索掩盖问题。

## 5. 退款与争议

- 必须引用原始 billing event、租户、用户、金额和幂等键。
- 支持部分和累计退款，累计不超过原始结算。
- 退款、余额回补、强配额冲减和退款事实必须同事务。
- 歧义目标、金额超限、指纹冲突或跨租户一律拒绝。
- 当前没有真实外部支付 provider 原路退款，不得把内部余额回补描述成银行卡退款。

## 6. 已付款订单中间态

当前 `paid/recharging` 没有自动恢复扫描，是发布阻断。出现悬空订单时：

1. 查订单、回调日志和效果账本。
2. 确认支付事实是否成立。
3. 对可幂等履约的订单使用管理重试入口。
4. 确定性无法履约的订阅单进入 `failed`，由人工退款或补偿。
5. 不直接改成 `completed`，也不直接给用户余额。

## 7. 恢复完成判据

- claim、hold、billing event、usage 和配额终态一致。
- 余额与双分录账本借贷平衡。
- 同一幂等键重放不产生第二次资金效果。
- 队列任务有明确终态和日志。
- 用户可查询到一致的用量、费用、退款和争议结果。
