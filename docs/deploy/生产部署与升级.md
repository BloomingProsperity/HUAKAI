# HUAKAI 生产部署与升级手册

> 事实基线：`origin/main@71abcf8e`
> 适用范围：`backend/docker-compose.prod.yml` 的 API-only 生产拓扑
> 重要边界：本文只描述当前源码可执行的操作，不代表项目已经通过上线门。

## 1. 生产拓扑

生产 Compose 包含：

- `gateway`：Go Gateway 与同镜像 Rust TLS Sidecar。
- `migrate`：在 Gateway 前执行全部 PostgreSQL 迁移的一次性任务。
- `postgres`：PostgreSQL 16，业务和恢复事实的权威存储。
- `redis`：Redis 7，承载可重建的共享短期状态，不作为钱路事实。
- `caddy`：公网 80/443、证书和 HTTPS 反向代理。
- `hermes-key-init`：初始化 Hermes 私钥卷；没有 Hermes 密钥时允许空操作退出。
- `hermes-runner`、`hermes-egress`：仅在 `hermes` profile 启用。

Gateway 只在 Compose 内网暴露 8080，不向宿主发布明文端口。公网流量必须先经过 Caddy。

## 2. 部署前检查

### 2.1 主机与网络

- Docker Engine 与 Compose 插件可用。
- 域名 A/AAAA 记录指向主机公网地址。
- 防火墙只对公网开放 80/443 和必要的管理 SSH。
- PostgreSQL、Redis、Gateway、Hermes 内部端口不得直接暴露公网。
- 生产数据卷和密钥目录位于持久磁盘，不放 `/tmp`。

### 2.2 必需环境变量

以 [`backend/.env.prod.example`](../../backend/.env.prod.example) 为字段入口，但值和默认行为仍以
[`config`](../../backend/internal/config) 与
[`docker-compose.prod.yml`](../../backend/docker-compose.prod.yml) 为准。

至少配置：

```text
HUAKAI_DATABASE_URL
POSTGRES_PASSWORD
HUAKAI_CREDENTIAL_KEY_B64
HUAKAI_SESSION_SIGNING_KEY_B64 或 HUAKAI_SESSION_SIGNING_KEY_HEX
HUAKAI_ADMIN_BOOTSTRAP_TOKEN
HUAKAI_RELEASE_MODE=production
HUAKAI_PUBLIC_DOMAIN
HUAKAI_AUDIT_LEDGER_BACKEND=postgres
HUAKAI_AUDIT_PRIVATE_KEY_HOST
```

生成命令：

```bash
# 凭据加密密钥和会话签名密钥应分别生成，不能复用。
openssl rand -base64 32
openssl rand -base64 32

# PostgreSQL 密码。
openssl rand -base64 24

# 一次性首装管理员令牌，结果必须是 hk_admin_ 加 24 位 Base32。
printf 'hk_admin_%s\n' \
  "$(head -c15 /dev/urandom | base32 | tr -d '=' | tr 'A-Z' 'a-z' | head -c24)"

# 日志账本签名私钥。
mkdir -p backend/secrets
openssl genpkey -algorithm ed25519 -out backend/secrets/audit_key.pem
chmod 700 backend/secrets
chmod 400 backend/secrets/audit_key.pem
```

真实 `.env`、数据库密码、审计私钥、会话密钥、凭据加密密钥和 Hermes 密钥不得提交 Git。

### 2.3 备份门

仓库当前只有备份清单 API，没有自动执行 `pg_dump`、`pg_restore` 或恢复演练的生产实现。
首次正式上线和每次迁移前，必须先按
[《备份与灾难恢复手册》](../runbooks/备份与灾难恢复.md)
完成数据库、凭据加密密钥、会话密钥和日志签名私钥的成套备份与恢复验证。

## 3. 首次部署

在仓库根目录执行：

```bash
cd backend
docker compose -f docker-compose.prod.yml config
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml ps -a migrate
```

成功标准：

1. `postgres`、`redis`、`gateway` 和 `caddy` 健康。
2. `migrate` 以退出码 0 完成。
3. 数据库迁移版本达到当前主线最高版本 `0220`。
4. `GET https://<域名>/healthz` 返回 200。
5. `GET https://<域名>/readyz` 返回 200。

`/healthz` 只证明进程存活；`/readyz` 当前还检查数据库、Rust TLS Sidecar 和共享限流存储。
任何 readiness 失败都表示实例不应接流量。

## 4. 首装管理员

`HUAKAI_ADMIN_BOOTSTRAP_TOKEN` 只在 `admin_tokens` 为空时创建首次管理入口。使用它进入管理 API 后：

1. 使用 bootstrap bearer 调用 `POST /admin/v1/admin-tokens/`，请求体至少包含
   `{"role":"platform_admin","name":"primary-operator"}`，签发正式 `platform_admin` 令牌。
2. 安全保存响应中只返回一次的 `plaintext_bearer`，并立即改用该新令牌执行后续操作。
3. 调用 `GET /admin/v1/admin-tokens/`，找到 `bootstrap=true` 且名称为 `bootstrap-admin` 的行。
4. 调用 `POST /admin/v1/admin-tokens/{id}/revoke` 吊销该 bootstrap 行，并再次列举确认状态为
   `revoked`。
5. 删除生产环境中的 bootstrap 明文并重启；确认旧 bearer 已返回 401，正式令牌仍可用。

也可以先通过正常用户注册创建账号，再使用 `HUAKAI_ADMIN_BOOTSTRAP_EMAIL` 提升平台工作租户内
的已有用户。两条路径用于不同恢复场景，不要同时长期保留。

## 5. Hermes

未启用 Hermes 时保持 `HUAKAI_HERMES_RUNNER_URL` 为空，不启动 `hermes` profile。

启用前先在 `backend/` 目录生成独立 JWT 密钥，并在生产 `.env` 中设置 Runner URL、
密钥目录和独立内部令牌：

```bash
./deploy/hermes-runner/generate-keypair.sh ./secrets/hermes
openssl rand -hex 32

# 将随机值写入生产 .env，不要直接提交或长期留在 shell 历史中。
# HUAKAI_HERMES_RUNNER_URL=http://hermes-runner:8801
# HUAKAI_HERMES_KEYS_HOST_DIR=./secrets/hermes
# HUAKAI_HERMES_INTERNAL_TOKEN_SECRET=<上一步的独立随机值>

docker compose -f docker-compose.prod.yml --profile hermes up -d
docker compose -f docker-compose.prod.yml --profile hermes ps
```

Compose 未显式覆盖时默认开启 LLM 提议；`.env.prod.example` 保留了显式关闭的注释示例。
提议本身不能直接修改系统；修改型工具仍必须经过当前租户权限、显式确认、并发限制和恢复记录。
不需要提议能力时设置 `HUAKAI_HERMES_LLM_PROPOSE_ENABLED=false`。
完整操作见 [《Hermes 运维助手手册》](../runbooks/Hermes运维助手.md)。

## 6. 日常检查

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=200 gateway
docker compose -f docker-compose.prod.yml logs --tail=200 caddy
curl -fsS https://<域名>/healthz
curl -fsS https://<域名>/readyz
```

同时检查：

- `/v1/admin/system/health` 响应体中的状态，不能只看 HTTP 200。
- `/v1/admin/ops/runtime-logs/health` 的丢弃数和失败批次。
- 告警事件、业务 DLQ、通知 DLQ、待对账 usage 和媒体孤儿。
- PostgreSQL 数据卷、备份产物和宿主磁盘余量。
- 节点监测中的稳定 `NODE_ID`；多副本不得重复。

## 7. 升级

1. 确认目标提交、镜像、迁移和本手册属于同一版本。
2. 完成数据库和密钥成套备份，并在隔离库验证可恢复。
3. 检查业务 DLQ、待对账 usage、媒体孤儿和 Hermes `recovery_pending`，避免带未知中间态升级。
4. 拉取目标提交，运行 `docker compose ... config` 和构建。
5. 先执行一次性 `migrate`；迁移失败时停止 Gateway 升级。
6. 启动新 Gateway，等待 `/readyz`。
7. 观察错误率、延迟、账号健康、结算恢复和日志健康。
8. 按发布记录保存提交、迁移版本、时间、操作者和验证结果。

裸机单实例可显式使用 `HUAKAI_AUTO_MIGRATE=true`，但生产 Compose 已外置迁移，不应同时开启。

## 8. 回退与故障

- 应用层可以回退到与当前 schema 兼容的旧镜像。
- 数据库不允许凭感觉执行 `migrate down 1`。只有迁移明确可逆且经过隔离库验证时才可下迁。
- 不兼容 schema 只能使用已验证备份恢复，或编写新的前向修复迁移。
- Gateway 停机前先摘流量并进入 draining；等待在途 HTTP 和 worker 收敛后再停数据库。
- 不直接 SQL 修改余额、账本、claim、退款、幂等效果或恢复队列。
