## 2026-07-23 来源信任重开切片

Owner 要求以最新主线起一个干净 PR，先闭环账号导入来源信任，再继续项目文档工作。本切片不复用旧工作树补丁，只在 `fix/account-intake-source-trust` 上处理以下真实缺口：

1. Claude Cookie、Claude Setup Cookie、CRS 同步和账号迁移包当前借用 `json_import` 进入统一计划，导致 OAuth-only 与 Setup-only 模式被错误拒绝。
2. CRS 暂存只校验厂商和处理器存在，没有把来源类型与生产归一化矩阵绑定；未来错误接线可能让 CRS 进入该来源从未产出的模式。
3. 泛化导入 HTTP 允许请求自行填写服务端专用来源，入口与专用流程的信任边界没有收口。
4. 暂存计划写入 PostgreSQL `jsonb` 后会重排 `json.RawMessage`，可能让执行重算哈希时误报计划漂移；调用方未提供显式时间时，计划与暂存也可能使用不同时间。

### 实现与影响半径

- 增加服务端专用来源：Claude Cookie、Claude Setup Cookie、CRS 同步、Codex Agent 和账号迁移包；通用 CLI/JSON/CSV 继续复用模式计划的允许来源。
- Cookie、CRS、Codex Agent 使用精确厂商/模式矩阵并 fail-closed；账号迁移包仅作为已授权、同租户的恢复来源，可恢复已发布且有生产处理器的模式，导入身份仍保持 `import_payload` 不可信等级。
- 泛化计划与执行入口拒绝 `oauth`、Cookie、CRS 和账号迁移包等服务端来源，专用路由继续承担权限、网络交换、短期暂存和恢复合同。
- 暂存记录保留参与计划哈希的原始 JSON 字节，并要求调用方在计划前固定 `Now`；不新增 schema，既有 15 分钟暂存记录可自然过期后重新预检。
- 爆炸半径覆盖账号创建/更新、凭据加密、身份消歧、套餐标签、健康初始化、代理恢复、日志和一次性流程状态；任何来源错配都必须在写库前拒绝。

4. 原子化社交建号与管理端建号，统一字段校验，补首装令牌、验证邮件重发和奖励恢复。
5. 更新迁移、OpenAPI、路由与判别式测试；按职责拆分超预算文件，删除本目标内的僵尸平行入口。
6. 跑专项测试、`go test ./...` 和带 `integration_pg` 的真 PostgreSQL 测试。
7. 更新唯一报告，执行未提交改动强制评审；只保留一个可审查 PR，合并仍由 Owner 决定。
8. 完成度复核发现 OAuth 执行终态原先落在账号事务之外：把账号/凭据/健康/业务日志、OAuth 会话终态和导入完成日志收敛进同一事务，并用完成日志写失败的真 PostgreSQL 变异场景证明不会留下孤儿账号或假成功。
9. 原子终态测试继续暴露 Grok OAuth 身份链缺口：生产换码器保存了 `id_token`，却没有验证并接入稳定主体，刷新材料变化时可能重复建号。先按当时授权码合同补齐 nonce、ES256/JWKS、issuer、audience、时效校验与受信 `sub` 投影；第 15 步又依据当前设备码合同替换该入口，最终实现以第 15 步为准。
10. 横向检查复合身份发现 OpenAI 工作区与 Grok 团队账号都可能被单独 `sub` 错误合并：共享账号域统一改为“账号范围 + 个人主体”复合消歧，同一人处于不同工作区/团队时分别建号，同一复合身份才允许轮换。
11. 核实套餐标签链发现统一 quota probe 已有 Grok/Codex/Antigravity 等适配器，但导入后只能等周期扫描。把账号导入事务提交后的 created/updated 事件接到单账号异步探测队列；触发失败由原周期扫描兜底，绝不把上游只读探测并入建号事务。
12. 横向复核设备码导入发现响应归一化会丢弃明确的通用套餐字段；保留该发行方证据并复用统一系统标签投影。没有上游证据的 Kimi 套餐仍保持 unknown，不伪造等级。
13. 全量门发现 `credentialacq` 主包越过 6000 行软预算；把设备授权共用 HTTP、大小限制和响应归一化下沉到 `oauthwire` 子包，不修改预算基线。
14. 未提交改动首轮复审发现 xAI 在缺少团队范围时会把个人主体退化为账号范围，同一用户跨团队可能误轮换凭据。按 xAI 官方 team 归属合同收紧为：共享账号 OAuth 必须同时得到已验签的个人主体与团队范围，缺任一项直接拒绝导入，不允许按个人主体猜测合并。
15. PR 通过后继续做完成度审计，发现 xAI 公共客户端被错误套入可变回调地址的授权码流程：现有 GET 回调要求 `flow_id`，通用 xAI 授权地址却无法可靠携带该值；固定公共客户端也不能冒充部署者自配客户端。依据 xAI 当前官方设备码合同和成熟实现的固定客户端行为，复用现有设备码加密暂存、轮询租约、失败恢复与账号导入预检，把 xAI 改为服务端设备码导入；成功换码后仍必须通过 OIDC 验签和团队范围校验。
16. 强制评审发现 access token 虽已验签并与 ID Token 主体绑定，却未校验目标 audience。官方发现文档只声明 `aud` claim、未公开取值；用 Owner 提供的既有测试令牌仅解码非身份合同字段后确认，真实 `aud` 等于固定公共客户端 ID。访问令牌验证因此再绑定该 audience，并补签名正确但 audience 错误时拒绝导入的判别测试。
