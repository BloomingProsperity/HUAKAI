## Final scope (synthesized)

### N+4a — Auth replacement only (THIS slice)

#### Schema migration `0009_l0_inbound_auth.up.sql`

```sql
CREATE TABLE IF NOT EXISTS users (
    id              bigserial PRIMARY KEY,
    tenant_id       bigint      NOT NULL REFERENCES tenants(id),
    email           text,                              -- nullable: signup not required in L0 minimum
    display_name    text        NOT NULL DEFAULT '',
    status          text        NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'disabled', 'deleted')),
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    deleted_at      timestamptz
);

-- Composite uniqueness so api_keys can FK on (tenant_id, id) — defeats
-- cross-tenant binding (Codex finding 2.4.4).
CREATE UNIQUE INDEX uq_users_tenant_id_id ON users (tenant_id, id);

CREATE INDEX idx_users_tenant_status ON users (tenant_id, status)
    WHERE deleted_at IS NULL;
CREATE UNIQUE INDEX uq_users_tenant_email ON users (tenant_id, lower(email))
    WHERE email IS NOT NULL AND deleted_at IS NULL;

CREATE TABLE IF NOT EXISTS api_keys (
    id              bigserial PRIMARY KEY,
    tenant_id       bigint      NOT NULL,
    user_id         bigint      NOT NULL,
    name            text        NOT NULL,
    key_hash        text        NOT NULL,             -- bcrypt hash; not bytea (bcrypt output is text)
    key_prefix      text        NOT NULL,             -- 16 chars including 'hk_live_' or 'hk_test_'
    status          text        NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active', 'disabled', 'revoked', 'expired')),
    expires_at      timestamptz,
    last_used_at    timestamptz,                       -- intentionally NOT updated in N+4 (CMB-7)
    revoked_at      timestamptz,
    revoked_reason  text,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    deleted_at      timestamptz,
    FOREIGN KEY (tenant_id) REFERENCES tenants(id),
    FOREIGN KEY (tenant_id, user_id) REFERENCES users(tenant_id, id)  -- composite FK
);

CREATE INDEX idx_api_keys_tenant_prefix ON api_keys (tenant_id, key_prefix)
    WHERE deleted_at IS NULL;
CREATE INDEX idx_api_keys_user_status ON api_keys (tenant_id, user_id, status)
    WHERE deleted_at IS NULL;
CREATE INDEX idx_api_keys_expires_at ON api_keys (expires_at)
    WHERE expires_at IS NOT NULL AND deleted_at IS NULL;
```

**Note**: NO FK from `billing_ledger_claims.api_key_id / user_id` → `api_keys / users`. Existing rows have synthetic ids (`tenantID*100+1`); adding ledger FK would break Phase B.5 fixtures. Deferred to N+4b.

#### sqlc queries `auth_inbound.sql`

```sql
-- name: LookupAPIKeysByPrefix :many
-- Returns up to N candidates matching the prefix; bcrypt verify is done in Go
-- to avoid putting the bearer plaintext on the wire to the DB.
SELECT id, tenant_id, user_id, key_hash, status, expires_at, deleted_at
FROM api_keys
WHERE key_prefix = sqlc.arg(prefix) AND deleted_at IS NULL
LIMIT 5;  -- guard against unbounded fanout

-- name: GetUserByID :one
SELECT id, tenant_id, email, display_name, status
FROM users
WHERE id = sqlc.arg(id) AND tenant_id = sqlc.arg(tenant_id) AND deleted_at IS NULL;
```
