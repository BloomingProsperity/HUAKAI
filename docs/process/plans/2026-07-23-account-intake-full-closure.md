## 一、统一行为合同

### 1. 入口与来源

1. 普通 JSON/CSV/CLI 继续禁止伪造 OAuth-only 或 Setup Token。
2. Cookie、CRS、加密迁移包使用服务端可信来源，不再降级成普通 JSON。
3. 同一供应商、认证模式和稳定上游身份只能形成一个账号；多命中必须显式冲突。
4. 静态 Key/云配置可直接创建；session/OAuth 一律进入标准计划、确认、执行和激活链。
5. 重认证必须指定目标账号，并验证返回的上游身份与目标库存一致。

### 2. 失败、日志与秘密

1. 可重试失败保留加密候选，状态保持可重试，并记录稳定错误码、严重级别和尝试失败日志。
2. 永久失败进入 `failed`，立即擦除临时秘密并记录终态日志。
3. 账号、凭据、健康、OAuth 会话、完成日志同事务；失败不得留下业务半状态。
4. 单账号更新、启停、删除与日志同事务。
5. 所有普通日志进入全局 30 天保留合同；凭据载荷、token、cookie 不得落日志。

### 3. 三身份

| 能力 | 部署者 | 获得能力的租户管理员 | 最终用户 |
| --- | --- | --- | --- |
| 平台租户账号 | 完整管理 | 禁止 | 禁止 |
| 租户自有账号 | 禁止跨租户代管 | 完整管理本租户 | 禁止 |
| 凭据创建/轮换/禁用/删除 | 仅自身工作租户 | 仅本租户 | 禁止 |
| 健康暂停/恢复/强制动作 | 仅自身工作租户 | 仅本租户 | 禁止 |
| 诊断与列表 | 仅自身工作租户 | 仅本租户 | 禁止 |
| 含秘密迁移包导出 | 自身工作租户 + 高强度认证 | 本租户 + 高强度认证 | 禁止 |

所有入口复用同一 resolver/capability 合同；能力存储不可用时返回稳定 503，禁止临时放行。

### 4. 套餐与 Day-2

1. 保留规范套餐、原始值、来源、可信度、验证状态和观测时间。
2. 新增可空的订阅开始、结束和上游明确到期时间；未知必须保持未知。
3. 批量命令逐项短事务，返回成功、失败、跳过、冲突和可重试信息。
4. 在现有健康状态机上补窄作用域动作，不把 6 态健康与渐进恢复压扁成启停。
5. 列表统计、凭据到期、会话窗口、模型同步和批量运维使用已有投影与服务，不重复造第二套。

## 二、执行批次

### Batch 1：恢复 OAuth 失败状态机和 CI

- 建立唯一错误分类：确认/计划/瞬时故障可重试，凭据/模式/上游明确拒绝为永久失败。
- 可重试失败持久记录尝试日志但不消费秘密；永久失败擦除秘密并进入终态。
- OAuth、Cookie、CRS 共用分类和完成逻辑。
- 修正当前 `integration_pg` 红测，不通过删断言或一刀切终结换绿。

### Batch 2：可信来源与唯一接入

- 修复 Cookie、CRS、迁移包来源映射。
- 增加 OAuth/Setup Token/API Key/CLI session 的计划、执行、攻击反向和 PostgreSQL 往返矩阵。
- 收口直接创建：静态材料保留，session/OAuth 转调标准链。
- 保留旧 API 兼容响应，但不保留第二套业务写入。

### Batch 3：权限、事务和重认证

- 抽出账号生命周期统一授权合同，并接到 intake、account、credential、health、recovery。
- 租户管理员获得能力后可闭环维护本租户凭据和健康；部署者不越级操作租户账号。
- 单账号更新、启停、删除与日志合入同一事务。
- 增加目标账号重认证，校验租户、供应商、模式和稳定上游身份。
- 含秘密迁移包导出接现有高强度认证证明。

### Batch 4：订阅时间与运营投影

- 以可空字段保存供应商明确返回的订阅开始、结束和到期时间，并保留证据来源与观测时间。
- 列表、详情、健康和诊断复用同一投影；账号 `expires_at` 不冒充订阅到期。
- 旧记录和不支持的官方 Key 返回“未知/不适用”，不伪造日期。

### Batch 5：Day-2 颗粒度

- 补批量刷新凭据、清错误/限流、测试、改池、改组内优先级，保持逐项部分成功。
- 补复制账号、上游模型同步预览、定时测试的后端合同和恢复状态。
- 核实现有代理与健康模块，优先复用已有服务和 SQL，禁止平行实现。

### Batch 6：清理与发布门

## 三、判别测试

| ID | 必须抓住的缺陷 | 层级 |
| --- | --- | --- |
| AT-AI-01 | 完成日志失败时业务整体回滚，可重试状态与失败日志一致 | PostgreSQL + fault injection |
| AT-AI-02 | 缺确认后可补确认重试，永久错误不能无限重试 | PostgreSQL |
| AT-AI-03 | 通用 JSON 不能伪造 OAuth-only，Cookie/CRS/迁移包可信来源可以 | unit + service integration |
| AT-AI-04 | 任一入口遇到同一稳定身份都更新同一账号，多命中显式冲突 | PostgreSQL + concurrency |
| AT-AI-05 | 直接创建 session/OAuth 不再绕过身份、项目、刷新和激活 | handler + PostgreSQL |
| AT-AI-06 | 部署者、租户管理员、最终用户三身份矩阵逐入口一致 | handler + PostgreSQL |
| AT-AI-07 | 单账号更新、启停、删除在日志失败时整体回滚 | PostgreSQL + fault injection |
| AT-AI-08 | 重认证只能更新目标账号，身份变化或冲突时拒绝 | PostgreSQL |
| AT-AI-09 | 含秘密导出缺少高强度认证时拒绝，成功时仍不泄密 | auth integration |
| AT-AI-10 | 套餐等级与订阅时间来源一致，未知不伪造成满额或未到期 | unit + PostgreSQL |
| AT-AI-11 | 批量动作部分成功逐项可见，失败项可安全重试 | PostgreSQL |
| AT-AI-12 | 清错误、清限流、重置配额只改目标状态，不误清其他健康信号 | PostgreSQL |
| AT-AI-13 | 多副本定时测试不重复执行，失败可诊断与恢复 | PostgreSQL lease + race |

每个测试必须断言最终数据库状态、日志、秘密擦除和 operator 投影，并记录删除哪个守卫后必须转红。
