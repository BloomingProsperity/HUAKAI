## 独立判断与执行顺序

1. 先建立端点证据表，记录路径、认证、Content-Type、必填字段、成功响应与错误响应；不从协议记忆补字段。
2. 把“协议表单状态 → 请求体”集中为无副作用纯函数。固定字段由表单控制，高级 JSON 只允许补充非保留字段，避免模型、输入或 stream 被暗中覆盖。
3. API 层分为 JSON 非流式、SSE 流式、二进制音频三条传输路径；所有路径复用既有 `src/lib/api` 基址/错误模型，网关调用继续只在请求头使用所选用户 API Key。
4. 页面按协议切换表单与响应摘要，保留模型和 Key 选择；流式协议显示增量文本和原始事件，向量只显示维度和前若干值，图片兼容 URL/base64，音频用对象 URL 播放并在替换/卸载时释放。
5. MediaTasks 在页面顶端新增入口，Modal 复用项目现有类名；成功后关闭并重新拉取当前列表，失败留在 Modal 内可恢复。
6. 测试以可判别 fixture 守住路径、方法、认证、关键字段、保留字段覆盖拒绝、空输入拒绝、不同响应载荷解析及创建后刷新行为所依赖的 API 契约。

## 参考项目范围与 clean-room 边界

- `CLIProxyAPI`、`sub2api`、`new-api` 为项目默认三镜范围，但本任务是 implementer lane，遵守 CR-R-001，不读取三者源码，也不作任何三者行为断言。
- 本实现只读取 HUAKAI 自有后端和前端源码；交互与样式仅复用 HUAKAI 现有模式，不复制外部 UI、目录、命名或文案。
- 本计划没有需要 Owner 在外部参考做法之间选择的决策点，因此不产生外部项目对照结论。

## 假设与风险记录

- 假设 `/v1/models` 返回的模型可用于所有协议；页面不擅自按协议过滤，实际兼容性由网关错误明确反馈。
- Gemini `{rest}` 由前端限制为相对模型动作路径，拒绝空路径、查询串和路径穿越；模型仍由现有模型选择器提供并拼入默认动作。
- 媒体 `parameters` 只接受 JSON 对象，避免数组、标量或无效 JSON进入后端。
- 本切片不新增危险动作、权限模型、密钥持久化或日志；Key 仍只存在页面状态和单次 Authorization 头中。
