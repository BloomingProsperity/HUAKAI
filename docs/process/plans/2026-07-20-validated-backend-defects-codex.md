## 核实结论

`#281/#282` 始终只作为问题线索；本分支未合并、未摘取、未移植两者提交。对照项目只读取行为并独立设计，没有复制源码、结构、注释、测试或内部标识。

### 已独立修复

- 凭据刷新：数据库账号槽负责准入，生产接线再用 PostgreSQL 会话级 advisory lock 强制同账号跨副本互斥；远端 HTTP 不占用数据库事务，锁连接异常时直接销毁连接防锁泄漏；成功和失败结果用短事务、版本 CAS、有限重试和提交结果复核持久化；持久化结果不确定时禁止再次交换旧令牌；Agent Identity 恢复补齐同一账号锁链。
- 用户会话：设备数检查、会话家族创建、刷新令牌和会话创建合并到同一事务；多服务实例并发仍严格遵守设备上限。
- 2FA：失败次数改为 PostgreSQL 原子累加，登录 2FA 使用严格限流桶；无效会话返回 401，存储故障返回 503。
- 账号池：绑定并发锁等待期间释放连接，避免小连接池饿死；选号热读不再偷偷更新健康状态。
- 协议与计费：补齐 completions 与 Anthropic token-count 超时；completions 大型流保留尾部 usage；rerank/completions 写入客户端工具归因；abort 场景保持计费上下文。
- 账号与代理：凭据兼容性校验使用真实租户并在查询故障时拒绝；代理解析保留租户 AAD；Bedrock 规范路径按段编码。
- 恢复与运维：续费扫描按 `(expires_at, id)` 稳定翻页，前页全跳过或单条失败也不会饿死后页；健康状态串行化冲突有限重试；Hermes 请求 ID 冲突拒绝；DLQ 失败原因在存储边界脱敏并按合法 UTF-8 边界截断；普通日志内存链按租户隔离。
- 缓存与策略：账号快照缓存全局限额、过期清理且不伪造可用值；moderation 尾角色不再绕过自动封禁。
- 删除重构后零调用的旧凭据事务 advisory-lock 实现，不保留误导性回滚路径。

### 核实后不改

- Device OAuth 秘密明文、设备入口校验、Telegram 时效、embeddings/rerank 响应前结算、配额恢复、fallback 状态等线索在当前 `main` 已有保护或已经修复，未重复改造。
- 外部支付上限属于当前默认关闭的未来直接支付路径，没有伪装成现网缺陷，也未擅自修改资金策略。

## 判别测试

- 刷新旧版本在锁等待期间被替换后，必须复用赢家或退出，不能发起旧凭据交换。
- 远端返回轮换凭据而首次持久化失败时，重试不得再次使用旧刷新凭据。
- 两个独立数据库连接并发创建设备会话时，最终活跃设备数必须精确等于上限。
- 从所有生产设备码入口写入后，数据库载荷不得出现明文秘密，轮询仍能正确解密。
- 删除任一生产接线后，对应测试必须失败，禁止只测 helper 存在。
