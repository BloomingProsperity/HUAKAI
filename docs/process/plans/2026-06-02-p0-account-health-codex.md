## Assumptions And Risks

- Platform admin without explicit scope follows the existing provider-account test handler default tenant scope of `1`.
- No admin audit row is added because this endpoint is read-only and the Owner brief did not request audit logging.
- Refresh metadata is selected by most recent `last_refresh_at`, then `updated_at`, then `credential_version`/`id`, among non-deleted and non-revoked credentials. If no v2 credential refresh metadata exists, the dedicated query falls back to legacy `provider_accounts.last_refresh_at` / `last_refresh_outcome`. Codex review found version-first ordering can be stale because `credential_version` is local to each credential row, and round 2 found legacy refresh metadata would otherwise be dropped.
- Clean-room risk is low: this implementation reads HUAKAI internal code and Owner-provided design only, with no reference-project source.

## Deferred Review Findings

Rationale: normal `platform_admin` tokens have `scope_tenant_id IS NULL`, so this endpoint inherits the existing provider-account admin default tenant `1` behavior. The Owner brief explicitly requested "same as existing resolveProviderAccountAdmin pattern" and no body-derived tenant override; changing this endpoint alone to accept a query tenant would create behavior divergence from adjacent provider-account routes. Follow-up: define a consistent platform-admin tenant selection rule for all provider-account admin read endpoints in the next admin-accounts slice. - [Fixed S1] Provider-account refresh fallback — source: Codex review round 2 P2, normalized to S1 because legacy provider-account credentials are still a supported account path. Fixed by coalescing v2 credential refresh metadata with `provider_accounts` refresh metadata and adding a discriminating integration test.
