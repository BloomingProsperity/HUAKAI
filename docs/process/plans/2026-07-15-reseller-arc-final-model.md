# 分销商(二级管理员)arc · 最终锁定模型(权威底稿)

日期:2026-07-15。Owner 逐问敲定、`/loop` 授权开工。**本文取代 2026-07-15-coadmin-and-merchant-tenant-arc-claude.md 中"协管员/三种角色/自定义权限引擎"的旧表述**(协管员概念作废)。codex 主推实现、Claude 主线并行、每 Phase 触 auth-core/schema/钱 = Owner 逐期点头。

## 0. 为什么(护城河=货源)
HUAKAI 开源可自部署,但自部署解决不了三样最难:服务器、干净代理线路、**能用的上游账号池**(第三样是真门槛)。平台把这三样全包,下游(分销商)开箱即用、挂自己牌子卖。市场实锤(调研 aaeda300):**账号池隔离是头号生死线**(Anthropic 封「同源多 token 高容量」),**不掺水+逐笔可对账是最锋利卖点**(实测影子 API 45% 不是宣称模型)。

## 1. 三套 UI(非三种角色)
- **用户 UI**:终端用户买额度、用 key、看自己用量。
- **系统部署者 UI(超管=Owner)**:单租户唯一掌控者,管一切。
- **二级管理员 UI(=分销商)**:一套**固定的、锁死在自己范围**的自助界面。**无内部协管员**(Owner 确认不需要)。

## 2. 钱账模型(全部 Owner 拍板,焊死)
1. **全预付**:用户、分销商都先付钱买余额。
2. **分销商=子站(child tenant)**:预付 Owner 买批发余额;**Owner 设其批发倍率=地板价**(超管专属,分销商碰不到)。
3. **分销商零售定价权**:在自己 UI 设**零售倍率**(须 ≥ 批发地板);下级在平台内按分销商零售价显示/扣费。
4. **下级真金不进平台账,分销商线下自收**(无提现/支付通道,Owner 无资金合规责任;Owner 只持分销商预付款)。
5. **两层原子扣费(最硬工程)**:一笔下级请求同一结算事务扣两层——①零售倍率扣下级余额 ②批发倍率扣分销商批发余额。复用现有 hold→settle 原子机制(settlement_intents),从单层扩成沿分销链多层;禁双扣/漏扣;重并发测试。
6. **fail-closed 两道闸**:请求先 hold 两层,任一不足即拒(下级零售余额见底 / 分销商批发余额见底→名下全停)。**Owner 批发层永远第一个被扣到**,分销商零售价再低亏的是他自己那层。

## 3. 架构落定
- **分销商 = 带 `parent_tenant_id` 的子租户**:零成本继承全表 `tenant_id` 隔离(0041 复合外键、公告 0102、配额 0070、账本 0002);child tenant 树天生支持多级(将来孙代理零改;scope=目标或其子树)。
- **权限:大幅简化,不建自定义勾选引擎**。分销商 UI = 一套固定自助功能集(管下级用户/发 key/分子额度/设零售倍率/看自己透明数据),全部 scope 锁自己子树。Owner 选"固定一套",将来精细化再加轻量开关。
- **96 条功能清单(调研 a3920a37)用途**:划边界线——🔴32(动钱/密钥/改批发价/凭证/审计导出/授权:**超管专属**)vs 分销商固定自助界面;不做逐条勾选引擎。⚠坑:争议裁决/孤儿对账/DLQ重放看着只读实则动钱,归 🔴。
- **上游账号**:共享池按额度扣 / 划专属账号,建站开关(两种都支持)。
- **透明**:分销商只看自己那摊真实数据——`billing_ledger_claims.provider_account_id/requested_model` vs `usage_records.upstream_model`(证不掺水)+ `pool_slot_acquisitions`(真并发)+ `quota_windows`(实时用量);shared_pool 下 provider_account_id 脱敏成「上游#N」(secret-mask)。
- **域名**:平台子域 / 自定义白牌域名开关(白牌+Host路由后置 Phase 3)。

## 4. 安全硬门(Owner 叮嘱,贯穿每 Phase)
- **SQL 注入**:全参数化(sqlc/手工镜像生成码同守),分销商任何输入(零售倍率/下级名/额度)禁拼接进 SQL。
- **IDOR 越权**:handler 级鉴权(HUAKAI 现状),**每个分销商 handler 必显式走 scope 校验(CanActOnTenant,读写只限自己子树)+ 拒绝测试**;`adminsessionauth/resolver.go:85-91` 现给 session 全权是最大越权面,必先收口。
- **提权**:分销商不能加平台权、不能改批发倍率(碰不到)、不能看/改凭证;不能操作别的分销商/超管。
- **钱账原子性**:两层扣费同事务、幂等键防重、对抗并发测试(双扣/漏扣/序列化冲突)达三缺陷 arc 强度。

## 5. 分期(每期独立交付+判别变异+真PG+并发+对抗审查零S0/S1+Owner点头)
- **Phase 1 — 子租户底座 + scope 强制 + 超管建分销商**:tenants 加 parent_tenant_id + 开关列;`CanActOnTenant` 泛化(含子树)+ session 全权收口;超管 UI 建/停分销商、设批发倍率、分账号。**[schema+auth-core]**
- **Phase 2 — 两层原子扣费 + 分销商自助 UI + 透明**:hold→settle 扩多层;分销商 UI 固定功能集(下级/key/额度/零售价/透明);fail-closed 两闸。**[钱+quota+billing 核心]**
- **Phase 3 — 白牌开关(后置)**:自定义域名 + Host→tenant 路由 + 独立公告 + dedicated 账号 + isolated 透明。**[部署/域名/TLS]**
