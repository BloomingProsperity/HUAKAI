## Task

Independently draft the implementation plan for **N+5 Slice 2 — Model Registry**.

### Goal

Replace the current "chat handler hardcodes ResolvedModel + threads pool_group_id directly" path with a real Registry layer that exposes:

```go
ResolveModel(ctx context.Context, publicAlias string, tenantID int64) (router.ResolvedModel, error)
```

Per `docs/specs/_invariants/cross-module-boundaries.md`:
- Registry is read-only (CMB-7).
- Registry feeds Router metadata only — NEVER credentials (CMB-1).
- Registry decides what `(publicAlias, tenant)` resolves to: canonical model id, capability set, protocol family, **candidate pool groups** (so Router can replace `PlanWithPoolGroupID` escape hatch).

### Required deliverables

1. **Schema migration** `backend/sql/migrations/0008_model_registry.up.sql` (+ `.down.sql`)
   - Tables you propose. Decide: one denormalized `model_aliases` table? or normalized `models` + `model_aliases` + `model_pool_bindings` + `model_capabilities`? Justify.
   - Tenant-scoping: tenant-specific overrides or global only? Trade-off.
   - Indexes for the hot path `WHERE tenant_id = $1 AND public_alias = $2`.
   - Seed data strategy: how do existing pool groups get a default alias so Phase C smoke still passes after deleting `PlanWithPoolGroupID`?

2. **`backend/internal/registry/` package**
   - `Registry` interface + `PostgresRegistry` impl.
   - `ResolveModel` query (SQLC).
   - Cache strategy: in-process LRU, snapshot version, TTL? Or no cache for L0?
   - Error classes: `ErrUnknownModel` vs `ErrModelDisabled` vs `ErrTenantNoAccess` vs `ErrRegistryBackend`. HTTP mapping.
   - Snapshot version: how `RoutePlan.SnapshotVersion` gets populated.

3. **Wire into `backend/internal/gatewayhttp/chat_completions_handler.go`**
   - Resolve `req.Model` (the `model` field in chat-completions JSON) through Registry to get `ResolvedModel`.
   - Pass `ResolvedModel` to Router; STOP threading `pool_group_id` through the request body.
   - Decide: keep the body's `pool_group_id` as a tenant-side override? Or refuse it (cleaner)? Trade-off.

4. **Delete `DefaultRouter.PlanWithPoolGroupID`** escape hatch.
   - All callers must go through `Plan(ctx, PlanInput)` with a Registry-resolved `ResolvedModel.PoolCandidates`.
   - Add `PoolCandidates []int64` to `ResolvedModel` if needed; explain why or why not.

5. **Backwards compat / smoke test**
   - Phase C smoke (`backend/cmd/gateway/smoke_test.go`) currently posts `pool_group_id` in body. What changes there?
   - Seed registry rows during `seedSmokeGraph` so the existing pool group gets resolved through a model alias.

6. **Decision points (D1–DN)** for Owner.
   - At minimum cover: D1 normalized vs denormalized schema; D2 cache yes/no; D3 tenant-override yes/no; D4 disabled-model HTTP code; D5 keeping body `pool_group_id` override.
   - For each, state the default you'd pick and why.

7. **Risk matrix**: what breaks if (a) two aliases map to the same canonical id, (b) tenant has no entry, (c) registry table empty at boot, (d) snapshot version mismatch between two concurrent requests.

8. **CMB compliance check**: walk through CMB-1, CMB-2, CMB-7 and prove Registry doesn't violate any.

9. **Test plan**: which integration tests must exist (table-driven), and which should be unit-only (cache eviction).

10. **Sequencing**: split or single PR? (N+4 was split N+4a/N+4b — does Registry warrant similar split?)
