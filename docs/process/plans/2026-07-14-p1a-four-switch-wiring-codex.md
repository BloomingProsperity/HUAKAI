## 功能形态清单

1. 渠道健康：429 进入 rate-limit 冷却；529/overloaded 进入其实际冷却分类；仅新事件读取新设置；旧截止时间保持不变。
2. 流式超时：构造 `TimeoutConfig` 时读取设置；`0` 保持“不限制”的既有语义；无显式设置回退接线前现实值。
3. 告警邮件：事件 firing 成功落库后，只有规则启用邮件时才通知；无收件人告警跳过；发送失败仅记录；规则冷却期间不重复发送。
4. 外部审核：本地 keyword/hash 检查始终执行；仅外部审核按 `0..100` 采样；跳过时按外部审核未启用路径放行且不产生外部调用成本。

## 判别性测试与变异自检

- 冷却：设置为 `X` 时断言截止时间约等于 `now+X`；删除设置读取会回到常量并失败；未配置时另断言仍等于接线前常量。
- 流超时：设置为 `Y` 时断言总流超时就是 `Y`；删掉接线会读到现实默认并失败；未配置时守住接线前值。
- 告警邮件：`true` 恰一封、`false` 零封、发送失败事件仍存在、冷却期二次触发仍一封；删除布尔守卫会使 `false` 用例失败。
- 审核采样：`0` 零外部调用且放行、`100` 全调用、中间值用确定随机源给出相反结果；删除采样判断会使 `0` 用例失败。

1. 盘点设置接口、默认值、运行时构造入口、告警持久化边界、审核本地/外部分界和现有测试夹具。
2. 列出确切目标文件，检查协调锁和工作树重叠，再扩大本会话锁范围。
3. 按“默认对齐 → 依赖注入 → 运行时消费 → 中文说明”的顺序实现渠道健康与流超时。
4. 按“持久化后置、复用冷却、fail-safe”的顺序实现告警邮件。
5. 在外部审核调用最窄边界注入采样器，保持本地检查顺序不变。
6. 补齐判别性单元/集成测试，逐包运行，再运行全量 build/vet；只有契约变动才跑 OpenAPI 门，只有前端变动才跑 vitest/tsc。
7. 检查差异、默认证据、变异说明和禁止项，释放协调锁并停下等待审查。
