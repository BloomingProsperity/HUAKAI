## Open Questions

1. sub2api 的 Codex 变换闭环本轮只读到导入/变换文件入口，未完整追踪到 gateway 执行全链路；不把它作为强 parity 结论。
2. HUAKAI Rust gateway 不在本 lane 生产数据面判断中；按 Owner 口径，Go `gatewayhttp` 是当前唯一生产数据面。
3. HUAKAI 长尾 provider 是否已有运维后台能力声明/价格/限流策略不在本 lane 读取范围内；本报告只按 gateway/provider 生产链路判定。
4. CLIProxyAPI 的 OpenAI-compatible 配置可覆盖任意上游，但是否有每个 vendor 的专属错误/价格/模型能力，本轮未逐 vendor 展开。
5. new-api 某些 channel 类型存在，但不同 adapter 的跨协议覆盖并不均匀；本报告只引用已读 adapter 区域，不推断未读 provider。
