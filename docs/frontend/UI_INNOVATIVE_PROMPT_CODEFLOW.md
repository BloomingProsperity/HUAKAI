# HUAKAI 前端 UI 创新设计提示词（带「代码流动效果」核心模块）

> 目标：为 HUAKAI（华凯）——MIT clean-room AI Gateway + 账号枢纽 + 运营管理平台，生成一个**极具新意**、富有技术美感的前端控制台 UI。
> 核心要求：必须包含一个**引人入胜的「代码流动效果模块」**（Code Flow / Live Code River），作为视觉与交互的灵魂，把 HUAKAI 独特的网关内部机制（请求 pipeline、HopChain、流式转发、池化索赔、mimicry）以动态、诗意却精准的方式可视化出来。
> 此提示词可直接喂给 Cursor、Claude Artifacts、v0、Lovable 或设计师，用于生成完整或单模块原型。

---

## 一、项目本质与 UI 灵魂（必须先理解）

HUAKAI 是一个 **operator 自托管的反向代理 + 多账号池化中转站**，核心价值是：

- 把多个上游 LLM 账号（OpenAI / Anthropic / Gemini / Bedrock / OpenRouter）池化成统一能力
- 健康感知路由、ClaimGate 资源占用、自动回退、重试、冷却
- 精确的 token 级计费 + 用量账本 + 可审计信任链（HopChain）
- 可选的强伪装（R7 应用层 6-step pipeline + R3 传输层指纹）
- 统一协议面 + 流式转发（SSE）

**UI 必须讲出这个故事**：不是普通的「API 管理后台」，而是**「看得见数据与代码在网关内部真实流动的神经中枢」**。

现有前端已实现基础 dashboard / playground / 用量 / 审计 / admin，但需要**全新视觉语言**，更沉浸、更技术诗意、突出「流动」。

---

## 二、整体设计语言（创新方向）

- **主题**：深空赛博操作台（Deep Space Cyber Ops）
  - 主背景：#05070f ~ #0a0c1a 极深蓝黑
  - 网格/细微星云纹理（subtle dot-grid + faint neural connections）
  - 强调色：
    - 电青 `#00f0ff`（流动数据）
    - 霓紫 `#a855f7`（路由决策）
    - 翡翠 `#10b981`（成功 / 健康）
    - 琥珀 `#f59e0b`（冷却 / 限速）
    - 猩红 `#ef4444`（错误）
  - 字体：Inter + 代码用 JetBrains Mono / Fira Code
  - 玻璃态 + 微光边（glassmorphism + neon glow），卡片带极细描边与轻微 blur

- **隐喻系统**：
  - 整个系统是一条「活的代码河流」（Code River）
  - 每个请求 = 一条发光的「代码脉冲」（code pulse / data packet）
  - 池化账号 = 河流中的「能量节点 / 涡流」
  - 网关内部处理 = 透明管道节点

- **动画哲学**：
  - 所有流动效果必须优雅、克制、专业（绝不廉价粒子爆炸）
  - 60fps 优先，性能开关（「节能模式」关闭重 GPU 效果）
  - 真实数据驱动：Playground 发请求时，真实流动包会点亮对应路径
  - 支持「历史回放」：点击任意历史请求，代码脉冲沿路径重放

## 三、核心创新模块：「代码流动舱」（Codeflow Nexus / 流码中枢）—— MUST HAVE

这是本提示词的灵魂，必须占据首页/概览最显眼位置（可折叠全屏）。

### 视觉与布局
- 占据 Dashboard 顶部 40%~55% 高度的宽幅区域（或独立「流码舱」标签页）
- 使用 `<canvas>`（推荐）或 SVG + Framer Motion 实现
- 布局为**水平 8 阶段管道**（可切换为径向/神经网络图）：
  1. Ingress（入口 / 认证）
  2. Auth & Registry（密钥解析 + 模型注册）
  3. Router Engine（路由计划）
  4. ClaimGate + Pool（资源索赔 + 池选择）
  5. Provider Adapter（上游适配）
  6. Stream Forwarder（流式转发）
  7. Billing / Obs Settler（计费与观测结算）
  8. Response Egress（响应出口）

每个节点是**半透明玻璃六边形 / 胶囊管道接口**，带：
- 节点名称（中英双语）
- 实时指标：RPS、p50/p99 延迟、活跃 lease 数、缓存命中率
- 状态光环（健康/降级/熔断）

### 代码流动效果细节（高保真要求）
1. **持续背景流**：
   - 细小的单色/霓虹代码片段（真实 JSON 片段、SSE 行、`data: {...}`、token 文本如 `"content":"你好"`）以极慢速度沿管道流动，像数字雨但只在管道内。
   - 使用半透明 monospace 小字 + 轻微发光 + 拖尾（trail fade）。
   - 密度可调（低/中/高）。

2. **真实脉冲包（Live Pulses）**：
   - 每当有实际请求发生（Playground 发消息、模拟请求、或 websocket 推送的实时事件），立即在 Ingress 端生成一个**发光胶囊状数据包**。
   - 数据包内部显示**极简代码摘要**（前 3 行关键 JSON 或模型名 + token 数）。
   - 数据包沿精确贝塞尔曲线 / 管道路径平滑移动（带速度变化：路由阶段快，池 claim 阶段稍缓）。
   - 移动时管道线段产生**霓虹脉冲光波**（subtle traveling highlight）。
   - 到达每个节点时有「接入」动画（节点短暂增强 glow + 指标跳动）。

3. **颜色与语义编码**：
   - 正常请求：青色脉冲
   - 命中缓存：紫色 + 更亮
   - 回退/多 attempt：分叉脉冲（主线 + 虚线支线）
   - 限速/冷却：琥珀色 + 速度变慢 + 小「⏳」图标
   - 失败：红色脉冲 + 在失败节点爆炸为小红点并快速淡出

4. **交互层**：
   - 鼠标悬停节点：高亮该节点所有历史/当前流动路径 + 显示 tooltip（最近 5 条请求摘要）
   - 点击节点：右侧滑出「节点详情抽屉」，内含该 hop 的实时日志流（过滤后的 SSE 行 + 结构化字段）、Top 账号、延迟分布小图。
   - 点击任意流动中的脉冲包：弹出「本次请求迷你追踪卡」，显示完整 HopChain + 选中账号 + 耗时 + 费用。
   - 顶部工具栏：
     - 实时 / 回放模式切换
     - 时间范围滑块（过去 5m / 30m / 2h）
     - 「注入测试脉冲」按钮（生成模拟不同场景的流动演示）
     - 过滤器：按模型 / Pool / User / 状态
   - 「河流视角」按钮：把整个画布切换为**从左向右无限滚动的河流视图**（像代码编辑器的 minimap + 流动日志结合），历史请求像漂流木一样从右向左进入视野。

5. **高级增强（可选但加分）**：
   - 背景极淡的「矩阵代码雨」只在画布外围，绝不干扰主流程。
   - 脉冲可展开为「迷你代码预览气泡」，hover 显示完整小段 prompt / response delta。
   - 支持「Mimicry 流」叠加：当 R7/R3 启用时，流动包会多一层「伪装改写层」视觉（包体出现短暂代码改写动画，显示 system rewrite / tool obfuscation 等步骤）。
   - 导出当前流动画面为 SVG / MP4（演示用）。

### 数据对接
- 理想：通过 SSE / WebSocket 接收真实 `request.flow` 或 `audit.hop` 事件。
- 降级：前端可先生成模拟真实数据的流动（基于 /debug/vars + /audit 拉取），并在 Playground 实际调用时「同步注入」流动事件。
- 必须能从真实审计 bundle（HopChain）回放流动。

## 四、其他页面如何呼应「流动」主题（保持一致性）

1. **Dashboard 概览**：
   - 顶部 = 代码流动舱（主舞台）
   - 第二行 = 4~6 个「脉冲 StatCard」：余额、今日 token 流出、活跃账号池、RPS、命中率。卡片右下角有极小的「迷你流动条」（像音频波形，但用代码片段密度表示流量）。
   - 快捷入口做成「能量节点」卡片，点击后有轻微「吸入流动」过渡动画到目标页。

2. **Playground（对话调试台）**：
   - 经典左右布局或上聊天下追踪。
   - 右侧或底部常驻**「本次请求流动追踪」**小画布：当流式响应开始，6 跳 HopChain 以微型流动方式实时点亮。
   - 响应气泡内部：token 逐个出现时，旁边有极小的「代码粒子」飞向流动舱（或本地小动画）。

3. **Pools / 账号池（Admin + 用户视角）**：
   - 用**节点图 + 流动连线**替代传统表格。
   - 每个 Provider Account 是一个可拖动的「能量球」。
   - 连线上的流动小点表示「当前正在 claim 的请求」。
   - 选中池后，流动舱可过滤只显示该池的脉冲。

4. **审计 / HopChain 页**：
   - 传统时间线升级为 **「可回放的河流」**：横向滚动，点击任意点即在主流动舱重放该请求的代码脉冲路径。
   - 增加 Merkle 证明的「信任光束」动画（从 response 节点射向 ingress）。

5. **用量 & 计费**：
   - 趋势图用「流动面积图」：面积由淡青色代码纹理填充，随时间「流动」向前。
   - 模型用量排行用「河流分叉」可视化（不同模型像支流汇入主河）。

6. **Mimicry 配置页**：
   - 把 R7 6 个步骤做成**垂直管道流动演示器**：开关一个 step，该 step 节点就会有「代码改写粒子」演示动画（system prompt 被重写、tool name 被混淆等可视化）。

## 五、技术实现约束与建议

- 框架：Next.js 15 App Router + TypeScript + Tailwind 4
- 动画：优先 `framer-motion` + 原生 Canvas (requestAnimationFrame) 或 SVG + motion
- 图表：保留 recharts，但流动舱独立实现（不依赖）
- 图标：lucide-react + 自定义极简管道/粒子图标
- 状态管理：Zustand 或 React Context（实时流动事件总线）
- 性能：
  - 流动效果默认只在视口内运行
  - 粒子数量上限（200~600）
  - 提供「静态模式」开关（无 canvas，仅静态管道 + 脉冲数量文本）
- 响应式：桌面优先（控制台特性），移动端优雅降级为简化流程图
- 真实集成：与现有 lib/api/*、SSE 解析、audit 类型保持兼容；新流动事件可先用 mock 事件总线
- 暗色优先 + 完美支持系统主题
- 双语：界面文案中英，优先中文（用户查询语言）

## 六、必须保留/体现的 HUAKAI 专业特性

- 清晰展示「池化」与「claim」概念（用户能直观看到资源被占用与释放）
- 强调可审计性（流动包点击后能看到 request_id / attempt_id / lease_id 链路）
- 危险操作（禁用账号、修改路由）必须有「流动确认」仪式感（脉冲必须先走完模拟路径才能真正执行）
- 健康状态、冷却、熔断要在流动舱和节点上实时可见
- 完全不泄露真实凭据（UI 永远 redact）

## 八、禁止事项（保持新意与干净）

- 不要照抄 sub2api / new-api / Helicone / Portkey 的现有界面布局与卡片风格

- 不要过度 3D（除非用轻量 @react-three/fiber 且可关闭）
- 保持专业：美观但不是玩具
