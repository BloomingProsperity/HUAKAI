# HUAKAI 全项目源码梳理 + 三家竞品对比 + 前端编写方案

> 文档性质:HUAKAI“马上开始写自己前端”的蓝图。
> 数据来源:多 Agent 纯源码梳理(9 功能域 × 4 项目 reader 读真码,逐域差异化综合),共 41 个 reader/综合 Agent 产出,装配成本文。
> 生成日期:2026-06-24。所有竞品功能均以**功能性中文描述**呈现(clean-room:不复制其源码标识符/组件名/字段名原文),`file:line` 仅作证据指引。

## 总述

HUAKAI 是一套对外卖 API 额度的中转站 SaaS(单租户多用户形态),技术栈为 Go 生产后端 + 自有 Rust tls-sidecar,后端能力在过去多轮迭代中已相当完整。**当前最大的、也是唯一卡上线体验的缺口是前端**:新选定的 React + Vite SPA 前端尚处于重建期,`frontend/` 目录除产物与说明外几乎没有业务源码,导致后端大量已接线的能力在界面上“零暴露”。

本次梳理对三家参考项目做了纯源码对照:

- **sub2api**(LGPL,Vue3 + Vite):**前端暴露面最强**的参考,几乎每个运维动作都有成熟界面。它是我们前端 IA(信息架构)与交互细颗粒的主要学习对象。
- **new-api**(AGPL,React):以“渠道(channel)”为中心的多上游网关,渠道/能力表/多密钥池/自动封禁等后端颗粒很细,前端运维台完整。
- **CLIProxyAPI**(纯 relay,Go 中转网关):**无面向用户的前端**,只有上游账号池转发与运维者向配置。在“账号/路由/模型目录”这类 relay 核心域有可借鉴的后端颗粒;在“计费/用户/令牌”等域则明确标注**无等价(relay-only)**。

**总判断**:HUAKAI 后端能力在多数域已追平甚至超过竞品(如可验证审计账本、分组倍率签名哈希链、多租户三层定价、tiered 定价 DSL、Rust 伪装出口等竞品都没有),**真正的工作量在前端重建**。本文第四节给出可直接开写的“模块 → 功能清单 → 优先级”蓝图,首批 P0 模块对应的后端端点均已就绪,前端纯接 API 即可落地。

## 一、HUAKAI 本项目梳理(源码实证)

按 9 域展开。每域含:(a) 一句话定位;(b) 中观模块列表;(c) 微观细颗粒功能(从源码梳理的功能树展开)。

### 1.1 上游账号管理（Provider Account / 上游凭据池）

**(a) 定位**:上游账号管理 = 中转站的“弹药库”:把多家上游(Claude/OpenAI/Gemini/Bedrock/Vertex 等)的凭据按账号纳管,负责增删改查、多模式凭据获取(OAuth/device_code/导入)、健康探活与运行态展示,是整条 relay 链的源头。

**(b) 中观模块列表**(共 16 个模块):

- 上游账号 CRUD（provider account 增删改查）
- 账号运行态展示（只读 DTO 字段）
- 凭据存储与加密（credentialstore）
- 账号凭据生命周期（每账号多凭据）
- 凭据获取流程（credentialacq）
- 账号模式目录（操作向导元数据）
- 凭据自动刷新调度器（credentialworker）
- 凭据轮转到期扫描（rotation due，opt-in 自愈）
- 账号凭据 Dry-Run 校验（非持久化测试）
- 账号健康状态
- 上游模型在线发现
- 批量与池组
- 出站代理绑定
- 混合渠道风险防护
- 上游账号身份自动提取（accountident）
- 多角色租户作用域鉴权

**(c) 微观细颗粒功能**:

#### 上游账号 CRUD（provider account 增删改查）

- 创建上游账号（provider_id/channel_id/name/account_type 六种类型/enabled/cap_concurrency/priority/static_weight/probe_model/tags/extra/model_allow_list/capability_flags；vendor+auth_mode 走 V2 加密凭据，否则旧 credentials JSON 直存；credential 创建失败软删账号防 orphan 入池）
- 列出上游账号（游标 base64 分页 limit≤200 + 按 pool_group_id/state_filter(active/error/disabled/rate_limited/overloaded/temp_unschedulable)/tag 多维过滤 + has_more/next_cursor）
- 查看/更新单账号（PATCH 指针字段省略=不动，可改 enabled/priority/static_weight/cap_concurrency/probe_model/tags/extra/model_allow_list/capability_flags/custom_error_codes/pool_mode/temp_unschedulable_enabled/temp_unschedulable_rules/proxy_binding）
- 启用/禁用账号独立端点（审计区分 enable/disable）
- 软删除账号（标 deleted_at + 审计）

#### 账号运行态展示（只读 DTO 字段）

- 健康/凭据态字段（health_state/credential_state/in_flight_count/last_dispatch_at/last_probe_latency_ms/last_probe_at）
- 限流/过载/临时停调态（rate_limited_at/rate_limit_reset_at/rate_limit_reason/overload_until/temp_unschedulable_until）
- 刷新与版本态（token_version/last_refresh_at/last_refresh_outcome/oauth_endpoint_health）
- 代理绑定态（proxy_id/proxy_group_id）

#### 凭据存储与加密（credentialstore）

- AES-256-GCM 信封加密（随机 nonce + 租户绑定 AAD + EncryptionScheme 标记 + KeyProvider 密钥轮换 + HMAC 指纹去重）
- vendor×auth_mode 模式注册表（16 vendor × ~20 auth_mode，每模式声明 required/anyOf 字段 + runtime kind + refreshable + allowGrace）
- 负载校验 ValidatePayload（必填/任一字段校验）
- 运行态物料解析（按 kind 抽密钥 + access_token→Bearer 降级 + 解析 extra 30+ 字段：org_id/project_id/base_url/auth_header/anthropic_beta/azure_api_version/cursor_checksum/cookie 等）
- 过期判定（非 allowGrace 模式过期直接 ErrCredentialExpired）

#### 账号凭据生命周期（每账号多凭据）

- 凭据 CRUD（GET/POST 列表与创建，create 支持手填 external_account_id/email 上游身份）
- 凭据轮转（rotate 换 payload 升 version）
- 凭据状态变更（active/revoked 等 + 审计）
- 凭据删除
- 凭据续期状态列表（renew-status 游标分页 + platform_admin 跨租户/按 tenant_id 过滤 + RenewStatusMetadata 监控将到期）

#### 凭据获取流程（credentialacq）

- OAuth PKCE 授权码流（返回 authorize_url/state/code_challenge；callback 校验 state 换码；finalize 落库；callback 式必须先 validated 才能 finalize 防回调注入）
- device_code 与 SSO 轮询流（copilot/openai-codex/kimi，豁免 validated 前置，按 auth_type 精确区分）
- 导入助手 粘贴/CLI/CSV/JSON/批量（解析单 token/JSON 对象/JSON 数组/CSV 多行→多 candidate；畸形 JSON 拒绝防当 raw token 吞；finalize=true 逐条落库返回 flows+finalized）
- 获取流程状态机（started→waiting_for_user→callback_received→validated→finalized / cancelled/expired/failed；终态拒写防重放 ErrFlowReplay；支持 Idempotency-Key）
- 获取流程取消端点（校验 flow 属本账号 + 生命周期审计）

#### 账号模式目录（操作向导元数据）

- account-modes 端点（每模式 required_fields(name/kind/secret/redaction/group/one_of_group) + allowed_helpers 白名单 + manual_first + long_lived_toggle + client_identity_source + is_enabled/is_experimental/feature_flag/risk_level+reasons）
- 隐藏实验性模式标记（openai-compatible 带 experimental+feature_flag）

#### 凭据自动刷新调度器（credentialworker）

- 快过期主动续（每 60s 扫 warning_window=15min 内将过期账号）
- 三级 storm 限流（account durable slot → per-vendor-endpoint → global）
- 退避重试（maxAttempts=3）+ CAS 写回（token_version+1 + refresh_fingerprint + last_refresh_outcome）
- 请求时热刷新 RefreshHotPath

#### 凭据轮转到期扫描（rotation due，opt-in 自愈）

- 超 maxAge 未刷新分类处理（refreshable OAuth/session → MarkForRefreshRecovery 保 active 拉 refresh_before_at 重铸；static api_key → 仅告警不下线防 brownout；needs_rotation 状态保留供强制轮转）
- 默认关（maxAge<=0 不扫）

#### 账号凭据 Dry-Run 校验（非持久化测试）

- 调 adapter 验凭据不持久化（持久化刷新模式返 operator_config_required 提示走调度刷新）
- error_class 分类（invalid_grant/rate_limit_exceeded/risk_control_triggered/account_disabled/payload_invalid 等 + 中文化建议）
- 用账号 probe_model 探测 + 写 dry_run 审计

#### 账号健康状态

- 健康详情端点（health_state+until / last_probe_latency_ms / model_sync_last_check_at / session_window_5h(5小时会话窗 start/end/status) / last_refresh_at+outcome / failure_class+count / requires_action / recent_requests ring 近期成功失败统计）
- 渠道健康手动干预（pause/resume/force-active 暂停/恢复/强制激活）
- 渠道健康查看（列表/summary/detail + cooldown_until/oldest_cooldown_at）
- 创建账号时初始化渠道健康记录（EnsureDefaultActive）

#### 上游模型在线发现

- upstream-models 端点（仅 upstream_passthrough 凭据，解密取 base_url+auth_header 经 SSRF 守卫拉 /models，返回 models[]+count，阻断私网/metadata 地址）

#### 批量与池组

- 按 tag 批量改账号（bulk-by-tag 批量设 enabled/priority/static_weight，上限 1000 行，逐行 UPDATE+审计，返回 affected_ids+count）
- 池组 pool groups CRUD（name≤64rune/top_k_default/capability_default(exact_capability_only|safe_equivalent_allowed)/allow_last_resort；create/update 与审计同事务回滚）

#### 出站代理绑定

- 三态互斥绑定（direct 清两列 / proxy 绑单 proxy_id 清组 / group 绑 proxy_group_id 清单代理；DB 触发器与 CHECK 兜底跨租户与互斥）
- 转发时账号级代理 vault 解析（按账号 proxy_id/proxy_group_id 解析出站代理 + 解密凭据供网关使用）

#### 混合渠道风险防护

- 创建账号时混合来源检测（pg_advisory_xact_lock 串行化 + ListProviderAccountRiskPeers 评估；HighRisk 未 confirm 返 mixed_channel_risk_confirmation_required 带 risks 项，需 confirm=true 复发；确认后审计记 mixed_channel_risks）

#### 上游账号身份自动提取（accountident）

- 从 OAuth token-exchange/id_token 提取上游 account_id+email（ChatGPT 用自定义 claim 端点；JWT 不验签仅作展示元数据；fail-open 不阻断；Source 区分 auto/manual；手填值兜底）

#### 多角色租户作用域鉴权

- 按 admin 角色限定 scope（tenant_operator 锁 scope_tenant_id；platform_admin 须 ?tenant_id=N 显式指定经 CanIssueForTenant 校验；body.tenant_id 必须匹配 scope 否则 403；凭据获取助手仅 platform_admin）
- 全部 mutation 端点带审计（InsertAdminAuditEvent，target_type=provider_account/account_credential）

### 1.2 渠道分组·池·路由选号

**(a) 定位**:渠道分组·池·路由选号 = 中转站的“调度大脑”:把账号编成池组,按模型→池绑定 + 多门选号链(花费/会话/窗口/健康/亲和)挑出本次请求落到哪个账号,决定容量利用率与稳定性。

**(b) 中观模块列表**(共 16 个模块):

- 池组与渠道分组管理 (pool_groups / channels)
- 账号候选拉取与资格过滤 (DBAccountSource)
- 15 道资格门有序链 (GateChain)
- 分层选号主流水线 (DefaultSelector)
- 模型→池/账号路由绑定 (model_pool_bindings admin CRUD)
- PASR 自有缓存亲和调度
- 5-mode 选号分发器 (SelectorDispatcher)
- 会话亲和与 sticky 绑定
- 并发槽位与排队 fallback (SlotManager / WaitPlan)
- 渠道健康状态机与失败转移 (channelhealth + PoolGate)
- 主动健康探测调度 (channelprobe)
- 计费熔断器 (circuitbreaker)
- 模型级 fallback 链 (modelfallback)
- 速率与花费/会话门(独立细颗粒)
- provider_account 路由字段运维编辑
- 选号原因审计 (RoutingReasonBuilder)

**(c) 微观细颗粒功能**:

#### 池组与渠道分组管理 (pool_groups / channels)

- 池组 CRUD 与软删(name/top_k_default/capability_default/allow_last_resort/enabled,唯一名 409,mutation 与 admin 审计同事务)
- 渠道归属池组管理(channel CRUD,(tenant,pool,name) 唯一约束,enabled+deleted_at 决定下属账号是否进候选)
- 租户作用域(tenant_operator 限本租户 / platform_admin 跨租户)
- 池组容量默认(top_k_default 1-10 / capability_default exact|safe_equivalent)

#### 账号候选拉取与资格过滤 (DBAccountSource)

- 按池组单次往返资格过滤(channels→provider_accounts→providers 三表 JOIN)
- SQL 层过滤 model_allow_list(@>requested_model)/capability_flags(@>required全集)/upstream_protocol/credential_state(valid|refreshing_with_grace)/health_state(冷却过期即时 normalize)
- ORDER BY priority,last_dispatch_at NULLS FIRST

#### 15 道资格门有序链 (GateChain)

- Tenant 门 / Lifecycle 门 / Channel 门 / Protocol 协议族精确匹配门
- Model 门 / modelRateLimitGate 模型级 429 反应式冷却门 / Capability 门
- Credential 凭据状态门 / Health 健康冷却门 + disable_cooling 逃生阀
- GroupPolicy 订阅分组策略门(fail-open 计数+WARN)
- Exclusion per-request 排除门(重试排已失败) / Pinned 强制选号门
- WindowCost 窗口花费门 / SessionCount 会话数门 / ContextWindow 上下文窗口门 / RatePrecheck RPM/TPM 预检门
- 门拒即记 GateFailureReason 跳过该账号 / nil 槽补默认门 / ForSelection 请求级门每 Select 查库一次缓存复用

#### 分层选号主流水线 (DefaultSelector)

- 四层顺序:sticky_within_routing → routing_affinity / sticky_standalone → fresh → 排队 WaitPlan
- fresh 候选稳定排序(Priority↑ → LoadRate↑ → LastUsedAt 最久未用)
- topK 抖动(同档头部并列取 K,K>1 mutex 保护下随机 Shuffle 均匀分散)
- selection_mode 策略:strict_priority 均匀 Shuffle / priority_weighted 按 static_weight 加权蓄水池抽样
- sticky miss 时下游剥 previous_response_id 防跨账号链 404
- NoCapacityError 携最早恢复时刻供 HTTP 层算精确 Retry-After(ErrAllChannelsDegraded / ErrNoEligibleAccount 可区分)

#### 模型→池/账号路由绑定 (model_pool_bindings admin CRUD)

- AdminBinding 字段:priority/weight/selection_mode/provider_model_id_override/rpm_limit/tpm_limit/max_parallel_requests/fallback_class/enabled/disabled_reason/effective_from/effective_until
- Serializable Tx 内 bump model_registry_snapshots.version,(tenant,model,pool) 唯一冲突
- model_id/pool_group_id 不可改(改身份走删+建)
- ModelAccountIDs 模型→账号子集定向路由(算法已实现,生产策略源未喂数=未点亮)

#### PASR 自有缓存亲和调度

- 以 SessionHash 为 prefix key,SegmentTable.LookupOrCreate 取 K=3 段
- 段内过滤健康+LoadRate<loadCap(默认0.95)
- score=Blend(localityBonus[有缓存?1:0] + headroom[(1-load)*0.3] - degraded[2.0]),并列取最久未用
- 段全不可用→HRW 全 ring 接力(TopK 选首个 healthy,degraded 兜底)
- per-tenant 分段防跨租户共段

#### 5-mode 选号分发器 (SelectorDispatcher)

- default 纯 DefaultSelector
- shadow 主走 default 异步 goroutine 跑 PASR 比对(500ms 独立 ctx,1024 buffered chan 非阻塞,累 match/diff/drop)
- canary 确定性采样桶(fnv64a(salt+sessionHash)%100<pct,pre-mutation 失败 fallback、post-mutation 失败 fail-closed 防双 claim)
- pasr-primary / pasr-strict
- 按 PoolSelectorConfig.Mode opt-in,default 模式不启动 PASR 基础设施(零回归)

#### 会话亲和与 sticky 绑定

- affinityrules 规则提取(ModelRegex/PathRegex/UserAgentInclude 匹配,从 request_header 或 gjson body 路径抽 key,ValueRegex 捕获组,可选 IncludeRuleName 前缀)
- affinityKey 赋给 sessionHash 驱动 sticky 与 PASR 分段(最大化 prompt cache 命中)
- DBStickyStore 持久化((tenant,session_hash,model)→account,Lookup 命中优先,被门挡则 miss 回退 fresh)
- best-effort Upsert,expires_at=now+TTL(默认1h 对齐 Anthropic extended cache)

#### 并发槽位与排队 fallback (SlotManager / WaitPlan)

- SlotManager.Acquire 原子占 in_flight(SQL in_flight<cap_concurrency 才+1)写 pool_slot_acquisitions
- 返回 AcquisitionToken + 幂等 ReleaseFunc
- 全部满载按头部账号构造 WaitPlan(MaxConcurrency/TimeoutMS/MaxWaiting,policy.FallbackTimeoutMS/MaxWaiting 可覆盖)

#### 渠道健康状态机与失败转移 (channelhealth + PoolGate)

- 状态机 active/degraded/cooling_down/ramping/disabled/manual_paused
- ApplySignal 窗口聚合判定(rate_limit 命中率/upstream_5xx 率/错误率/p99 延迟超阈→degrade/cooldown;ban→直接 disabled+高危告警可需 operator_ack)
- 恢复走 ramp 1%→10%→50%→100% 灰度放量,失败回滚+指数退避 cooldown(封顶5级)
- PoolGate 接入 GateChain.Health,ramping 按 fnv32(admissionKey)%100<rampPct 概率准入
- 运维操作:手动暂停/恢复/强制激活(force-active 触发 security 告警)+ 列表/summary(by_state 计数+oldest_cooldown_at)/详情(含审计事件)

#### 主动健康探测调度 (channelprobe)

- 按 interval(默认1min)ticker 列活跃渠道逐个跑 ActiveProbe
- ClassifyWithConfig 分类(状态码/错误码/延迟/本地网关错误)→ApplySignal 喂状态机
- ctx 取消即停,探测错误只 WARN 不中断

#### 计费熔断器 (circuitbreaker)

- 按不透明 key 隔离的 Closed/Open/HalfOpen 状态机(连续失败默认5开闸,Open 默认1min 后转 HalfOpen 限量探测)
- fail-closed(默认)/ fail-open(放行但 ServingUntracked)模式
- ForceOpen/ForceClose 运维强制 + StateOf 只读快照

#### 模型级 fallback 链 (modelfallback)

- 按错误类(general/context_window_exceeded/content_policy)查 model→候选链 map(支持 * 通配)

**(c) 微观细颗粒功能**:

#### 用户自助 Key 生命周期 (userkey + userkeyhttp)

- 签发 Key:name 必填≤128、environment=live|test(拒 admin 前缀)、expires_at 三态(空=永不/未来时刻/拒过去)
- 明文 bearer 仅创建时一次性返回 + notice 提醒立即保存,后续 GET 只回 key_prefix
- 单用户活跃 Key 上限 20(事务内 advisory lock + count,≥20 返 409 防并发越界)
- 列出自己名下 Key(含已撤销、created_at DESC、limit 默认50上限200、tenants/users 双 JOIN 强制 active)
- 取单条详情(tenant+user+id 三元组,归属不符统一 404 防枚举,返回 status/expires_at/last_used_at/revoked_at/revoked_reason)
- 撤销自己的 Key(reason≤256字节、FOR UPDATE 锁、幂等 AlreadyRevoked、软撤销保审计)
- 批量撤销(ids 1-200去重、逐条幂等、缺失落 not_found 数组而非整批失败)
- 局部更新 PATCH(指针区分省略/显式、name/status/expires_at 三态、clear>set>unchanged 优先级、拒过去时间)

#### 新建 Key 默认配额种入 (default_quota + config)

- 签发同事务内按 DefaultKeyQuota 种 api_key scope 的 quota_policies
- 默认 RPM(requests/fixed-60s,默认60)+ 并发(concurrency/windowless,默认5)
- mode=enforce、priority=200、created_by_actor=system_default
- limit<=0 维度跳过、Enabled=false 整体关闭
- scope_id=key.id 与 relay 请求时 quotaenforce 口径一致(请求前必被 Reserve 命中)

#### 每-Key 控制面 (userkeycontrols + userkeycontrolshttp)

- 每-Key 配额设置/查看:metric=cost-usd|request-count、window_kind=calendar-day|week|month|fixed、mode=enforce|observe|manual_first|disabled、limit≤8位小数;读端附 used_usd/remaining_usd/window_end
- 每-Key IP 白名单:裸IP归一/32或/128或CIDR、去重掩码归一、空=不限制、CSV 存储、请求时 prefix.Contains 判定未命中403
- 每-Key IP 黑名单:同归一存储、请求时 deny 先于 allow 判定、命中403
- 每-Key 模型白名单:模型名小写归一去重、空=不限制、gateway 在原生与转换两路径路由前判定403
- 每-Key 绑定配额分组:group_id 可null解绑、设置前校验组属本租户、读返回 group_name/description/enabled

#### 过期清扫与命名空间 (apikeyexpiry + apikeyns)

- 过期 Key 后台清扫 Worker:默认每5分钟、SweepExpiredKeys 批量(500/批循环到0)、RunOnce 手动触发、Start/Stop 生命周期
- 请求时解析器即时过滤(expires_at 已过则跳过候选,不依赖 worker)
- 命名空间/前缀真相源:客户 live/test 前缀 base 默认 hk、可经 env 覆盖([a-z0-9]{1,6}非法启动期 fail-loud)
- admin 前缀 hk_admin_ 刻意不可配(operator 权限边界)、ValidCustomerFormat 做 DB 查询前廉价过滤

#### 入站 Bearer 鉴权解析 (auth/api_key_resolver)

- 解析 Authorization: Bearer,取16字符 prefix 做前缀索引(LIMIT 5 候选)
- 逐行 bcrypt.CompareHashAndPassword(cost 10、MaxBcryptFanout=5)
- 校验 status=active + expires_at 未来 + user/tenant active(INNER JOIN 软删过滤)
- best-effort touch last_used_at(100ms 超时、失败不拒)
- 凭据级失败统一 401 不区分 revoked/expired/not-found 防枚举、基础设施故障 503、明文绝不入日志

#### 运营/管理员侧 Key 管理 (admin + adminhttp)

- 跨用户签发:platform_admin 全局/tenant_operator 本租户、RBAC CanIssueForTenant、校验目标 tenant+user active、限速30次/小时/actor、写 admin_audit_events
- 列出租户 Key:platform_admin 须显式传 tenant_id(无全舰队列)、limit 1-500、租户不存在404
- 撤销租户 Key:软撤销(disabled/expired 也翻 revoked)、幂等、deny 审计写 tenant_id=NULL 防污染他租户

#### Bearer 生成·脱敏·审计 (admin/keygen + userauditlog)

- GenerateBearer:<namespace>_<24字符小写base32>(120位熵、去 0/O/1/I 歧义便于手抄)、prefix 取前16字符
- IssueResult.String() 自动脱敏明文为 <redacted> 防 fmt 泄露
- 签发/撤销审计 payload 只含 key_prefix/tenant/user 绝不含明文或 hash
- 用户自助 Issue/Revoke 写 structured slog + 可插拔 UserAuditSink(默认 NoopSink)

#### 分组定价倍率(pricingcatalog ratio_resolver + admin + 审计)

- RatioResolver 按 (tenantID,poolGroupID) 解析 group ratio,默认 1.0
- 30s TTL 缓存 + NotFound 缓存为 1.0
- 后端抖动优先返回 last-known-good 否则 1.0 放行 + 标记 PendingReconciliation + expvar 计数

- 写后精确失效 resolver 缓存
- 签名审计哈希链 + GET /audit/verify 重放报告首条被篡改记录

#### 分层/阶梯定价 DSL(billingdsl + pricingeval resolver)

- 检测 tiered 数据则解析 billingdsl 表达式
- 按 input/output/cache_creation/cache_read 桶分层求值,否则走 FlatCost
- tiered 解析/求值失败 fail-soft 回退 flat + 标记 PendingReconciliation
- 支持 5m/1h 缓存创建分层、per_unit、model_multiplier、group_ratio
- 微 USD ÷ 1e6

#### 工具调用附加费(toolpricing + 施加)

- 按 (tenantID,modelID) 查 web_search/file_search/image_generation 每千次 USD 价
- Surcharge = price/1000 × count × group_ratio,additive 叠加 Total
- 零计数/零价/空表 = 零附加费(默认安全)
- 计费默认开(env unset/空→启用,非法值 fail-safe 朝启用不漏钱)
- 平台默认价 web_search $10 / file_search $2.5 / image_generation $0
- per-(tenant,model) override 两层回落,Source 永不为 nil

#### 缓存价覆盖(cache-price-override)

- admin GET 列表/PUT 设置/DELETE 清除 /v1/admin/cache-price-overrides

## 三、差异化分析(我们 vs 三家)

**总判断**:**sub2api 前端暴露面远胜我们**——HUAKAI 后端能力齐全(多处反而更深),但前端处于重建期、业务源码近乎为零,导致这些能力在界面上无法运维。因此差异化的主旋律不是“补后端功能”,而是“把已有后端能力用前端暴露出来”,并在此过程中**择优借鉴**竞品已验证的细颗粒交互。下表逐域汇总“竞品有而我们缺或更细的颗粒”。

## 四、我们的前端编写方案(开写蓝图)

这是本文重点。按各域的前端模块建议汇总:**前端分哪几个模块**、**每个模块放哪些功能**(含从竞品学到的细颗粒)、以及 **优先级**。

### 4.0 优先级口径

- **P0(上线必做)**:对应已生产接线、后端就绪的核心能力,前端纯接 API 即可,缺它则该域无法运维。
- **P1(拉齐颗粒度)**:与 sub2api/new-api 拉齐体验的重要细颗粒,部分需后端小幅补强。
- **P2(增强)**:锦上添花或 money/security/部署敏感、走 Owner-gated 的项。

### 4.1 上游账号中心（Account Hub / 上游账号管理）

**域级优先级**:P0（上线必做）

**功能清单**:

- 【账号列表页】游标分页表格(limit≤200 + next_cursor) + 多维筛选条(state_filter active/error/disabled/rate_limited/overloaded/temp_unschedulable + pool_group_id + tag + 搜索) + 排序;表格列含名称/account_type/vendor/enabled/health_state/credential_state/in_flight_count/priority/static_weight/cap_concurrency/proxy 绑定/last_dispatch_at;借鉴 sub2api:ETag 304 增量刷新 + 自动刷新轮询(5/10/15/30s 存 localStorage)+ 批量拉今日统计

**落地说明 / 排序建议**:该模块是 HUAKAI 前端从零落地本域的蓝图。P0 先把已有后端(平台设置54-key/公告/健康聚合/告警单指标/签到)接出来形成可用运维台;P1 补告警多指标、运维监控趋势、Hermes 助手、日志诊断、版本SMTP——这些是与 sub2api/new-api 拉齐颗粒度的关键;P2 备份/数据保留/导航可见性为增强。注意三条 HUAKAI 独有强项(Hermes 诊断助手+每日巡检、加密随机签到入账billing、告警静默维度抑制)前端要充分展示而非只对标竞品。备份与在线升级两块对外卖额度 SaaS 有运维价值但 money/security/部署敏感,走 Owner-gated。反克隆:设置/运维的导航与交互按 HUAKAI 自有 React 栈(管线即导航+Cmd-K)设计,不照搬任一竞品外壳。

### 4.9 安全与信任中心(Security & Trust Center)——含四个子页:1)审计与信任(Audit & Trust) 2)告警中心(Alerting) 3)内容审核中心(Content Moderation) 4)风控与访问控制(Risk & Access Control)

### 4.10 建议的前端模块树(收尾)

基于以上 9 域,建议 HUAKAI 自有前端(React + Vite SPA,go:embed 单二进制)组织为如下顶层导航 → 模块树。导航按“能力管线”而非照搬竞品外壳组织(遵循反克隆方向):

```
HUAKAI 控制台
├─ 上游侧(运营者)
│  ├─ 上游账号中心(Account Hub)           [P0]
│  ├─ 路由与池管理中心(Routing & Pool Hub) [P0]
│  └─ 定价与模型目录(Pricing & Catalog)    [P0,含对外公开广场页]
├─ 用户侧(终端用户自助)
│  ├─ API Key 令牌管理(我的密钥)           [P0]
│  ├─ 用量与计量中心(Usage & Metering)     [P0]
│  ├─ 钱包/充值/订单/兑换码(Billing & Wallet)[P0 钱包+充值,P1/P2 增强]
│  └─ 账户与认证(Auth & Account 自助区)     [P0]
├─ 平台侧(管理端)
│  ├─ 用户/租户/权限管理(Admin Users)       [P0]
│  ├─ 运营统计仪表盘(Admin Analytics & Ops) [P0/P1]
│  ├─ 系统与运维中心(System & Ops Console)  [P0]
│  └─ 安全与信任中心(Security & Trust)      [P0,差异化卖点]

   ├─ 模型广场 / 价目表
   └─ 注册 / 登录 / 公开用量查询
```

> 数据地基(最先接线):**sitepublic 公开设置端点**下发的开关驱动所有认证/功能能力的显隐与校验;**单位换算基础设施**(USD/分 ↔ 元)是所有计费与定价 UI 的公共底座。两者应在首个迭代里打底。

### 4.11 首批 P0 模块开写顺序

以下顺序兼顾“后端已就绪可直接接线”“上线核心链路依赖关系”“最快形成端到端可演示”三点:

1. **认证地基 + Auth & Account(自助登录注册)** —— 先接 sitepublic 开关与单位换算底座,打通登录态,后续所有页面依赖它。
2. **上游账号中心(Account Hub)** —— relay 链源头,后端 account-modes/凭据获取/健康/Dry-Run 已全就绪,前端纯接 API。
3. **路由与池管理中心(Routing & Pool Hub)** —— 把账号编池、绑模型、选号链与健康运维暴露出来,让“调度大脑”可运维。
4. **API Key 令牌管理(我的密钥)** —— 用户出货口,`/v1/api-keys/*` 已挂载并鉴权,直接照功能清单接线。
5. **用量与计量中心(Usage & Metering)** —— 用户用量明细 + 配额自查 + 时序图 + 导出 + 审计日志,后端端点已就绪。
6. **定价与模型目录(含公开广场页)** —— 变现门面 + 对外获客页,分组倍率/缓存价覆盖 admin 后端可直接用。
7. **钱包 + 充值门户(Billing & Wallet 的 P0 子集)** —— 钱包余额 + 充值闭环(手动 admin 充值已可替代支付 provider),订单/兑换/分销等增强项预留槽位但默认灰显。
8. **用户/租户/权限管理(Admin Users)** + **系统与运维中心** + **安全与信任中心** —— 管理端三件套,把已建后端逐一暴露;安全与信任中心要把“可验证审计账本/Merkle 链/成本收据失配退款”做成可演示的差异化卖点页。

> 排期提示:第 1–5 步即可形成“注册登录 → 配账号 → 编池路由 → 发 Key → 看用量”的端到端可演示闭环,是上线体验的最小集;第 6–8 步补齐变现与管理面。所有 P0 模块的后端端点均已在源码中接线,前端不存在被后端阻塞的项。
