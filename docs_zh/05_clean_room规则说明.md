# Clean-Room 规则说明

必须保持功能不缩水，目标是功能对齐或更强。

参考项目只能作为事实证据，不能作为代码来源。

可以学习：

- 用户行为。
- 业务流程。
- 功能清单。
- 风险和 bug 模式。
- 公开 issue 中暴露的场景。
- 测试思路。

不能复制：

- AGPL/GPL/LGPL 等非 MIT 项目的源码。
- 独特目录结构。
- 注释。
- 数据库 schema。
- UI 源码和独特样式。
- 实现细节和内部命名。

许可证风险只能改变实现方法，不能删除功能。
