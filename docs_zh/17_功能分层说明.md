# 功能分层说明

这个文件用来解决“项目太大、功能太多、不知道先做什么”的问题。

每个功能都分成 4 个建设等级：

- L1：最小可用。
- L2：生产可用。
- L3：参考项目对齐。
- L4：比参考项目更好。

## 举例：账号池

L1：

- 手动配置一个或几个 provider key。
- 能启用、禁用。
- 请求时能选一个可用账号。

L2：

- 支持多个账号。
- 支持轮换、状态查看、失败排除。
- 日志里能查到用了哪个账号。

L3：

- 支持账号池。
- 支持权重、优先级、余额或额度状态。
- 支持异常隔离和健康检查。

L4：

- 自动调度。
- 成本优化。
- 预测账号风险。
- 自动降级和告警。

## 举例：计费

L1：

- 只记录 usage，不真正扣费。

L2：

- 做简单 quota。
- 超额拒绝。
- 保存价格上下文。

L3：

- 支持余额、充值、扣费、倍率、模型价格。
- 支持账本和管理员修正。

L4：

- 支持对账。
- 支持利润分析。
- 支持异常成本检测。

## 第一版应该做什么

第一版优先做：

- API Key 接入。
- Gateway Core。
- Provider Account Hub。
- 基础 Routing。
- Model Registry。
- OpenAI-compatible 协议转发。
- Usage Logging。
- 简单 Quota。
- Admin Lite。
- 基础安全和日志。

## 第一版先不做什么

这些不是删除，只是后面做：

- 完整计费账本。
- 充值扣费。
- 复杂智能路由。
- 自动账号池优化。
- 完整插件系统。
- 完整后台功能对齐。
- 多租户组织。
- 高级风控。
- 合规导出。

## 对 Owner 的意义

你不用在“全做”和“不做”之间选。

正确选择是：

- 第一版做 L1。
- 第二阶段补 L2。
- 后面补 L3。
- 最后追求 L4。

这样既尊重实战项目的经验，又能真的做下去。
